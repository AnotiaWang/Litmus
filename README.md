# Litmus · LLM 交易决策基准

一个**长期追踪不同大模型（LLM）交易决策能力**的基准：同一时刻、同一份行情、同样的初始资金和风控规则，让多个模型各自决定买入、卖出还是观望，按成绩排名，看谁的判断更好，也看它们能不能跑赢“一直持有”和简单的均线规则。

- **模拟撮合**：按每一轮行情快照的价格成交，所有模型用同一个价格，手续费 0.1%。不连接任何交易所账户，不会真实下单。行情来自 Binance 公开行情接口，不需要 API Key
- **分赛季**：交易对、初始资金、决策周期、风控等规则在赛季开始时定下，赛季内不能改；要换规则就开新赛季，所有模型从初始资金重新开始。历史赛季的成绩和记录随时可以切换回去查看
- **公开浏览**：默认任何人都能看排行榜、收益率曲线和每一条决策记录（不含 Provider 地址和 Key）；管理页需要口令。也可以关闭公开浏览
- **在网页上管理模型**：Provider（任意 OpenAI 兼容接口）和模型都在管理页添加，不用改配置、不用重启

> ⚠️ 本项目仅供学习和研究，不构成任何投资建议。成绩只说明“这段行情里这个模型这样决策会怎样”，不代表未来。

## 它每一轮做什么

默认每 15 分钟一轮（按整点对齐），每一轮：

1. **取一次行情**：已收盘的 K 线和当前价格，这一轮所有模型都用这同一份快照
2. **每个模型各自决策**，互不影响，一个模型出错不影响其他模型：
   - **LLM 模型**：每根 K 线（默认 1 小时）收盘后问一次。发给它最近若干根 K 线（默认 48 根，含成交量）、这些 K 线覆盖不到两周时再加最近 14 根日线、程序算好的行情摘要（最近 1 / 4 / 12 / 24 小时的涨跌、离 24 小时高低点的距离、ATR14、成交量相对均量的倍数）、当前价、它自己的账本、持仓均价和浮动盈亏、持仓时长、止损线、距止损的 ATR 距离、风控规则和当日已用 / 剩余次数、冷却和累计手续费，以及它最近 3 次决策和最近 3 笔成交（卖出带已实现盈亏）。不提供均线、RSI 这类指标：它们是均线基线的判断依据，给了模型容易被直接套用，各模型的决策会趋同。它返回动作（买 / 卖 / 观望）、比例、把握程度和理由。超时或输出不合格时重试一次，仍失败就观望；输出被截断（`finish_reason=length`）不再重试
   - **均线基线**（对照组，不调用 LLM）：SMA20 连续 2 根 K 线在 SMA50 上方时买入，在下方时全部卖出；RSI14 高于 70 时不追高
3. **止损**：每轮都按当前价检查，跌破就全部卖出，不等模型
4. **风控**：当日亏损熔断、每日笔数、冷却时间、单笔上限、仓位上限、最小下单额——只会调小金额或拦下交易，所有模型用同一套
5. **模拟成交并记账**：每个模型有自己的账本，记录资产快照

真正问过 LLM、触发止损、规则给出买卖信号或出错的轮次都有完整记录：LLM 的理由、思考过程、原始输出、提示词、耗时、token 用量，风控说明和成交详情。

LLM 成功率只看模型作答的那些次：输出不合格算模型失败；超时、网络、HTTP 错误是服务的问题，不计入成功率，单独统计。

## 部署

需要一台装好 Docker（含 Docker Compose）的 Linux 服务器。

```bash
cp .env.example .env
nano .env                       # 填 ADMIN_TOKEN，可以用 `openssl rand -hex 24` 生成
docker compose up -d --build
```

`.env` 里只有三项：`ADMIN_TOKEN`（管理口令，必填）、`PORT`（默认 8000）、`DATA_DIR`（数据库目录，默认 `./data`）。其余都在管理页里设置。

然后浏览器打开 `http://服务器IP:8000/admin`，输入口令：

1. **Provider** → 添加：名称、接口地址（如 `https://api.openai.com/v1`、`https://openrouter.ai/api/v1`）、API Key
2. **模型** → 添加模型：选 Provider，填模型名（可以点“获取模型列表”从接口拉取）、显示名、曲线颜色，可选思考强度（`reasoning_effort`）、超时和额外请求参数（JSON，原样合并进请求体，用来开启各家不同的思考参数）。添加后点“测试”用当前行情问一次，确认能用
3. 等下一轮自动运行，或在“概览”里点“立即运行一轮”

首次启动会自动创建“第 1 赛季”（BTCUSDT、每个模型 1500 USDT、1 小时决策、激进风控）和均线基线。想换规则就到“赛季”里开始新赛季。

自检（检查行情接口，并用当前行情把每个参赛中的模型问一次，不记录、不交易）：

```bash
docker compose run --rm -e SELFCHECK=1 app
```

## 页面

- **排行榜**（首页）：赛季信息和规则、样本不足提示、所有模型的收益率曲线（从所选时间范围的起点算起，虚线是同期一直持有，带买卖点和持仓区间）、回撤 / 仓位子图、排行榜（收益率、对比一直持有、最大回撤、平均仓位、已实现 / 浮动盈亏、手续费、成交和盈亏比、LLM 成功率、p95 耗时和估算成本）、所有模型的买卖记录。点模型进入详情
- **模型详情**：这个模型的资产、持仓、止损价、收益率 / 回撤 / 仓位曲线、LLM 统计，和均线基线对比，以及它的全部决策记录
- **方法**：数据来源、模拟撮合假设、决策节奏、风控、提示词版本、时区和局限性
- **管理**（需要口令）：
  - 概览：暂停 / 恢复（暂停期间不询问 LLM、不交易，止损也不执行，资产照常记录）、立即运行一轮、模型健康面板、公开浏览开关
  - 模型：添加、测试、修改显示名 / 颜色 / 超时 / 成本单价、暂停 / 恢复、归档、删除
  - Provider：添加、修改（Key 留空表示不改）、删除
  - 赛季：当前赛季的规则、开始新赛季、改名、历史赛季

数据每 30 秒自动刷新，页面在后台时暂停。支持手机浏览器和深色模式。

### 模型的身份

Provider、模型名、思考强度和额外参数决定了模型“是谁”，**创建后不能改**，否则同一条曲线里混着两个模型。要换就新建一个，再把旧的归档。显示名、颜色、超时、成本单价随时可以改。

- 新添加的模型从下一轮开始，以当前赛季的初始资金参赛
- **暂停**：停止参赛，不询问 LLM、不交易；账本、持仓、成绩和记录都保留，可以恢复
- **归档**：停止参赛，成绩停在最后一次资产快照，持仓不做处理；历史成绩和决策记录保留。归档不能恢复
- **删除**：只有还没参与过运行的模型能删除；参与过的只能暂停或归档
- **成本单价**：可选的输入 / 输出 token 单价（美元 / 百万 token），只用于面板估算成本，不影响交易

### 赛季规则

| 规则 | 默认值 | 说明 |
| --- | --- | --- |
| 交易对 | BTCUSDT | 以 USDT 计价的现货 |
| 初始资金 | 1500 USDT | 每个模型相同 |
| 决策周期 | 1h | 每根这个周期的 K 线收盘后问每个模型一次（可选 15m ~ 1d） |
| 运行间隔 | 15 分钟 | 两次询问之间的轮次只检查止损、记录资产 |
| 发给 LLM 的 K 线 | 48 根 | 10 ~ 100 |
| 风控 | 激进 | 保守 / 温和 / 激进三种预设，或自定义 |

**决策周期建议用 1h 或 4h。** 15m 每天要问 96 次/模型，token 和延迟更高，信号也更容易被噪声主导；30m 是 48 次/天。赛季表单会在选择高频周期时给出提醒，并显示 `llmKlines` 覆盖的小时数。

**版本**：赛季开始时会把当时的提示词版本和引擎版本写进赛季。如果之后升级代码导致版本变化，页面会提示“赛季中途混用了版本”，建议开新赛季；每个赛季的实际提示词仍然保存在每条决策记录里。

风控预设：

| | 止损 | 移动止损 | 单笔上限 | 仓位上限 | 每日成交 | 冷却 | 当日亏损熔断 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 保守 | 3% | 5% | 25% | 50% | 4 笔 | 120 分钟 | 3% |
| 温和 | 5% | 关闭 | 50% | 80% | 6 笔 | 60 分钟 | 5% |
| 激进 | 10% | 关闭 | 100% | 100% | 12 笔 | 关闭 | 15% |

护栏越紧，各模型的结果越接近——管得越多，测出来的越是程序的风控而不是模型的判断，所以默认用最宽松的“激进”。

几个细节：

- **卖出不受限**：卖出不受单笔上限、每日笔数、冷却时间约束，当日亏损熔断期间也照常卖出（熔断只停止买入）
- **比例**：买入时是动用账本可用 USDT 的比例；卖出时是卖掉持币的比例，可以只卖一部分（剩下的不够最小下单额时改为全部卖出）
- **立即运行一轮**不受“每根 K 线问一次”的限制，会马上问所有 LLM 模型

## 回测

可以用历史行情看看**均线基线**在当前赛季规则下过去会怎么交易：

```bash
docker compose run --rm -e BACKTEST=1 app                        # 最近 90 天
docker compose run --rm -e BACKTEST=1 -e BACKTEST_DAYS=180 app   # 最近 180 天
```

用和线上同一套信号、止损、风控和记账代码逐根回放，输出收益率、同期一直持有的收益率、最大回撤、成交明细等。只读取数据库里当前赛季的规则，不写入。

LLM 模型不回测：每根 K 线都要调用一次，成本太高；模型训练时多半见过这段历史行情，结果也会偏乐观。

## 日常操作

```bash
docker compose logs -f              # 看实时日志
docker compose stop                 # 停止（会等当前这一轮跑完）
docker compose start                # 重新启动
git pull && docker compose up -d --build   # 更新代码后重新部署
```

- 数据库和日志都在 `./data`：`./data/litmus.db`、`./data/logs/app-YYYY-MM-DD.log`（保留 14 天）
- 想从头开始：先 `docker compose down`，删除 `./data`，再 `docker compose up -d`
- **从旧版本（单模型的 AI 交易助手）升级**：旧数据库的结构不兼容，启动时会自动改名为 `litmus.v1-时间.db` 保留下来，然后从空数据库重新开始。`.env` 里旧的 `BINANCE_*`、`LLM_*`、`SYMBOL` 等变量不再使用（启动日志会列出来），可以删掉，Provider 和模型到管理页里重新添加

## 安全建议

- 管理页只有一个口令保护，**建议放在 Nginx + HTTPS 后面**
- Provider 的 API Key 保存在服务器的数据库里（`./data/litmus.db`），注意这个文件的访问权限和备份；页面和接口只返回打码后的 Key，日志会自动脱敏
- 公开浏览时，任何人都能看到模型名、Provider 显示名、决策记录和 LLM 的完整输出；不想公开就在管理页关闭

## 开发

技术栈：Node 24、pnpm、Nuxt 4（Nitro 服务端）、Nuxt UI 4、TypeScript、SQLite（`node:sqlite`）、Chart.js。

```bash
pnpm install
cp .env.example .env   # 填好 ADMIN_TOKEN
pnpm dev               # 开发服务器 http://localhost:3000
pnpm lint
pnpm typecheck
pnpm test              # 单元测试 + 端到端测试（不访问网络）
pnpm test:unit         # 只跑单元测试，速度快
pnpm build             # 生产构建，产物在 .output/
pnpm backtest          # 回测（需先 pnpm build；BACKTEST_DAYS=180 pnpm backtest）
pnpm exec nuxt task run trade:run   # 开发时手动触发一轮（需先 pnpm dev）
```

目录结构：

```
app/                 前端（纯客户端渲染）
  pages/             排行榜、模型详情、管理、方法
  components/admin/  管理页的各个标签（含模型健康面板）
server/lib/          核心逻辑（纯 TS，不依赖 Nuxt 自动导入，便于单测）
  config.ts          环境变量校验
  auth.ts            口令校验
  db.ts              SQLite 读写：Provider、模型、赛季、决策、资产快照
  market.ts          Binance 公开行情 + 模拟行情
  engine.ts          一轮的编排：取行情 → 每个模型决策 → 风控 → 模拟成交（含运行锁）
  strategy.ts        均线基线的指标和信号
  llm.ts             LLM 决策（OpenAI 兼容接口）+ 模拟 LLM
  risk.ts            风控规则
  ledger.ts          账本和资产计算
  admin.ts           管理操作（Provider、模型、赛季、站点设置）
  views.ts           排行榜、曲线等接口数据
  runtime.ts         运行时：数据库、定时、各模型的决策器
  logger.ts          日志（自动脱敏）
  selfcheck.ts       部署自检
  backtest.ts        回测（真实引擎 + 模拟行情 + 历史 K 线）
server/tasks/        Nitro 任务 trade:run
server/plugins/      启动、定时触发、优雅退出
server/middleware/   公开浏览 / 管理口令校验
server/api/          JSON 接口（/api/admin/* 需要口令）
shared/settings.ts   赛季规则、风控预设和站点设置的校验（前后端共用）
shared/agents.ts     Provider 和模型的表单校验（前后端共用）
shared/versions.ts   提示词 / 引擎版本号，写进赛季用于检测中途升级
shared/types/        前后端共用的数据类型
tests/               Vitest 单元测试与端到端测试
```
