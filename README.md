# Litmus · AI 交易助手

一个用来**学习 AI 辅助交易完整流程**的自动交易程序：规则策略产生信号 → 大模型（LLM）复核 → 风控把关 → 在交易所的模拟盘（虚拟资金）下单，并在网页面板上查看每一轮的决策记录。目前对接的是 Binance 现货的 Demo Mode 和测试网。

> ⚠️ 程序只能连接 Demo Mode 或测试网，代码里写死了地址白名单，**无法连接真实交易环境**；也没有任何提现、划转、借贷功能。它不以盈利为目标，策略也很简单，请把它当作学习工具。

## 它每一轮做什么

默认每 15 分钟一轮（下面提到的参数都可以在面板「设置」里调整）：

1. **取行情**：最近 100 根已收盘的 1 小时 K 线和当前价格
2. **规则信号**（默认趋势模式）：
   - 持仓时，现价跌破止损线（持仓均价下方 5%）→ 立即卖出
   - 持仓时，短期均线（SMA20）连续 2 根 K 线在长期均线（SMA50）下方 → 卖出；RSI 止盈默认关闭，开启后 RSI 高于设定值 → 止盈卖出
   - 空仓时，SMA20 连续 2 根 K 线在 SMA50 上方且 RSI < 70 → 买入
   - 其余观望。只在空仓时买（不加仓），只在持仓时卖
3. **风控预检**：熔断、每日次数、冷却时间、有没有钱、仓位还有没有空间——注定下不了单就到此为止，不浪费 LLM 调用
4. **LLM 复核**（只复核买入）：大模型判断买入是否合理，并决定动用多少比例；它只能否决或调小。卖出（含止损）不经过 LLM，直接全部卖出
5. **风控**：按单笔上限、仓位上限、最小下单额算出最终金额，只会调小
6. **下单并记账**：程序只在设置的预算（默认 100 USDT）内交易（“策略账本”），Demo 账户里其余的虚拟资金不会动

无论停在哪一步（观望、被否决、被拦截、出错），这一轮都会完整记录下来，面板上可以逐条展开查看原因。同一根 K 线上的同一个信号只处理一次，不会每 15 分钟重复下单。

上面是默认的**规则模式**。面板「设置」里可以把决策方式切换为 **LLM 决策**，见下文。

几个细节：

- **两种信号模式**：`trend`（默认）看均线当前在上方还是下方，服务中途停过也不会错过；`cross` 只在均线交叉的那根 K 线上买卖，信号更少。可以先用回测比较两种模式
- **信号确认**：均线在交叉附近常常来回穿越，trend 模式要连续 N 根（默认 2）已收盘 K 线都在上方 / 下方才买 / 卖，减少“刚买就卖”的来回交易和手续费。设为 1 就是不确认
- **止损**：止损（默认 5%）按持仓均价（含手续费）计算；移动止损（默认关闭）按持仓以来的最高价计算，能锁住一部分浮盈。止损每轮都按当前价检查，不用等 K 线收盘
- **止损 / 止盈后不马上买回**：trend 模式下止损或止盈卖出后，要等 SMA20 先回到 SMA50 下方、再重新站上去才会再买，避免“止损 → 买回 → 再止损”或“止盈 → 追高买回”
- **RSI 止盈默认关闭**：回测里开启止盈（RSI 80）在各个时间段都比关闭差——它会在上涨途中提前卖出。需要时可以在设置里打开
- **卖出不受限**：卖出是降低风险的操作，不受单笔上限、每日次数、冷却时间约束；**当日亏损熔断期间也照常卖出**（熔断只停止买入，否则熔断反而会让止损失效）。手动暂停期间不会下任何单，包括卖出

## LLM 决策模式

不用均线和 RSI 规则，由大模型直接决定买入、卖出还是观望，以及动用多少比例。在面板「设置 → 决策方式」里切换，马上生效。需要在 `.env` 里配置 LLM 连接信息。

- **问 LLM 的频率**：默认每根 K 线收盘后问一次；也可以改成每 N 分钟问一次（按整点对齐）。运行间隔照旧，没到询问时间的轮次只检查止损。点「立即运行一次」不受频率限制，会马上问一次
- **发给 LLM 的内容**：最近若干根已收盘 K 线（默认 48 根，含成交量）、当前价、策略账本、持仓均价和浮动盈亏、止损线、风控限额、现在能不能买 / 卖，以及它自己最近 10 次的决策和最近 5 笔成交。不发送均线、RSI 等指标，判断完全交给 LLM
- **比例**：买入时是动用账本可用 USDT 的比例；卖出时是卖掉持币的比例，可以只卖一部分（剩下的不够最小下单额时改为全部卖出）。可以加仓
- **程序仍然负责止损和风控**：止损 / 移动止损每轮都按当前价检查，跌破就全部卖出，不等 LLM；风控规则和规则模式一样，只会调小金额或拦下交易
- **出错时观望**：LLM 超时或返回不合格时重试一次，仍失败就观望，这个时段不算问过，下一轮重试
- **省调用**：暂停时、或者现在既不能买（冷却、次数、熔断、仓位满）也没有持仓可卖时，不调用 LLM
- **没法回测**：每根 K 线都要调用一次 LLM，成本太高；模型训练时多半见过这段历史行情，回测结果也会偏乐观。LLM 决策模式下运行回测命令，会按面板里规则策略的参数回测，供对比参考

## 部署步骤

需要一台装好 Docker（含 Docker Compose）的 Linux 服务器。

### 1. 开通 Binance Demo Trading 并创建 API Key

1. 登录 Binance 账户，进入 **Demo Trading**（模拟交易，使用虚拟资金）
2. 打开 Demo Trading 的 [API 管理页面](https://demo.binance.com/en/my/settings/api-management)，创建一个 API Key（选系统生成的 HMAC 类型）
3. 只需要勾选“读取”和“现货交易”权限，**不要**开启提现等其他权限
4. 记下 API Key 和 Secret Key（Secret 只显示一次）

> 想用测试网（testnet.binance.vision）也可以：在测试网网站上用 GitHub 登录后生成 Key，并在 `.env` 里设置 `BINANCE_ENV=testnet`。Demo Mode 的价格更贴近真实市场，推荐优先使用。

### 2. 准备 LLM

任意 OpenAI 兼容接口都可以（OpenAI、DeepSeek、通义千问、本地 Ollama 等），需要三项：接口地址（如 `https://api.openai.com/v1`）、API Key、模型名。

用推理模型时可以用 `LLM_REASONING_EFFORT` 设置思考强度（如 `low` / `medium` / `high`，可选值以服务商文档为准）。思考越深，单次复核越慢：每次请求最多等 `LLM_TIMEOUT_SECONDS` 秒（默认 30，最多 120），超时会重试一次，仍失败就按否决处理。自检会显示 LLM 实际耗时，可以据此调整。

不想用 LLM 时三项都不填；填了也可以随时在面板「设置」里关闭。关闭后规则信号直接进入风控，金额按单笔上限。

### 3. 填写 `.env`

```bash
cp .env.example .env
nano .env        # 或用你习惯的编辑器
```

必须填写的项：

| 配置项 | 说明 |
| --- | --- |
| `BINANCE_API_KEY` / `BINANCE_API_SECRET` | 第 1 步创建的 Key |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 第 2 步的 LLM 配置（不用 LLM 时都不填） |
| `ADMIN_TOKEN` | 面板口令，可以用 `openssl rand -hex 24` 生成一个随机口令 |

其他项都有默认值，含义见 `.env.example` 里的注释。配置有误时程序会拒绝启动，并在日志里逐项说明原因。

预算、运行间隔、策略和风控参数不在 `.env` 里，启动后在面板「设置」里调整（见下文）。

### 4. 启动

```bash
docker compose up -d --build
```

### 5. 自检

```bash
docker compose run --rm -e SELFCHECK=1 app
```

会依次检查网络、时间同步、交易对、API Key、账户余额（是否够面板里设置的预算）、LLM，每一项输出“通过”或失败原因。只查询，不下单。全部通过就说明配置正确。

### 6. 打开面板

浏览器访问 `http://服务器IP:8000`，输入 `ADMIN_TOKEN`。口令只保存在当前浏览器里。

## 面板怎么看

- **状态栏**：运行中 / 已暂停（及原因）、下次运行时间；可以暂停、恢复、立即运行一次。暂停期间每轮只记录信号，不下单
- **账户卡片**：策略账本的资产总值、策略收益率，以及同期“启动时全部买入 BTC 一直持有”的收益率，方便对比策略是否真的有用；持仓时还会显示持仓均价和止损价
- **资产曲线**：策略（绿色实线）与“一直持有”（橙色虚线）
- **决策记录**：每轮一行，点击展开可以看到指标数值、LLM 的完整理由和原始返回、风控说明、成交详情和错误信息；可以只看买卖信号
- **设置**（右上角齿轮）：预算、运行间隔、决策方式（规则 / LLM 决策）、K 线周期，止损和风控参数；规则模式下是信号模式、均线和 RSI 参数、LLM 复核开关，LLM 决策模式下是询问频率和发给 LLM 的 K 线根数。保存后从下一轮开始生效，不用重启；正在运行的一轮不受影响

数据每 30 秒自动刷新。支持手机浏览器和深色模式。

### 修改预算

修改预算等于**重新开始策略账本**：下一轮按新预算重新初始化账本，收益率、“一直持有”基准和资产曲线都从那时起重新计算，之前的决策记录保留。所以有几个限制：

- 持仓期间不能改，要等策略卖出、回到空仓
- 正在运行一轮时不能改
- 保存前会查询 Demo 账户，可用 USDT 少于新预算时不保存（否则下一轮核对账本会自动暂停）

## 回测

上线前（或调参数之前）可以先用历史行情看看这套策略过去会怎么交易：

```bash
docker compose run --rm -e BACKTEST=1 app                          # 最近 90 天
docker compose run --rm -e BACKTEST=1 -e BACKTEST_DAYS=180 app     # 最近 180 天
docker compose run --rm -e BACKTEST=1 -e SIGNAL_MODE=cross -e STOP_LOSS_PCT=3 app   # 临时换参数试试
```

回测从 Demo Mode 拉取历史 K 线（只读公开行情，不下单），用和线上**同一套**信号、止损、风控和记账代码逐根回放，最后输出策略收益率、同期一直持有的收益率、最大回撤、成交次数、盈利次数、手续费和每笔成交明细。

回测使用面板里当前的设置（只读取，不改动正式数据库）。想临时换参数，用 `-e` 传入，只对这一次回测生效，不会改面板里的设置。可用的变量名：`BUDGET_USDT`、`KLINE_INTERVAL`、`SIGNAL_MODE`、`CONFIRM_BARS`、`SMA_FAST`、`SMA_SLOW`、`RSI_PERIOD`、`RSI_BUY_MAX`、`RSI_SELL_MIN`、`STOP_LOSS_PCT`、`TRAILING_STOP_PCT`、`MAX_ORDER_USDT`、`MAX_POSITION_PCT`、`MAX_TRADES_PER_DAY`、`COOLDOWN_MINUTES`、`DAILY_LOSS_LIMIT_PCT`。

和线上的差别，看结果时要心里有数：

- 不调用 LLM，买入金额按单笔上限（线上 LLM 可能否决或调小）
- 每根 K 线收盘时跑一轮，止损也只在收盘时检查（线上每个运行间隔检查一次，触发得更早）
- 按收盘价成交，不考虑滑点
- 测试网只保留最近一小段数据，回测请用 Demo Mode

回测结果只说明“过去这段行情里会怎样”，不代表未来。

## 日常操作

```bash
docker compose logs -f              # 看实时日志
docker compose stop                 # 停止（会等当前这一轮跑完）
docker compose start                # 重新启动
docker compose down                 # 停止并删除容器（数据保留在 ./data）
git pull && docker compose up -d --build   # 更新代码后重新部署
```

- 数据库和日志都在 `./data` 目录：`./data/litmus.db`、`./data/logs/app-YYYY-MM-DD.log`（保留 14 天）
- 想从头开始（清空账本和记录）：先 `docker compose down`，删除 `./data` 目录，再 `docker compose up -d`
- 修改 `.env` 后需要 `docker compose up -d` 让新配置生效；面板「设置」里的参数改了马上生效，不用重启
- 从旧版本升级：预算、运行间隔、策略和风控参数以前写在 `.env` 里，现在改到了面板「设置」，`.env` 里的这些行不再生效（启动日志会列出来），可以删掉，再到面板里重新设置。已经开始运行的账本会保留原来的预算

## 安全建议

- 面板只有一个口令保护，**建议放在 Nginx + HTTPS 后面**，或用防火墙限制只有你自己的 IP 能访问 8000 端口
- `.env` 里有密钥，不要提交到仓库，也不要发给别人
- 程序不会把 Key 和口令写进数据库、日志或接口返回

## 开发

技术栈：Node 24、pnpm、Nuxt 4（Nitro 服务端）、Nuxt UI 4、TypeScript、SQLite（`node:sqlite`）。

```bash
pnpm install
cp .env.example .env   # 填好后
pnpm dev               # 开发服务器 http://localhost:3000
pnpm lint
pnpm typecheck
pnpm test              # 单元测试 + 端到端测试（不访问网络）
pnpm test:unit         # 只跑单元测试，速度快
pnpm build             # 生产构建，产物在 .output/
pnpm backtest          # 回测（需先 pnpm build；用面板里的设置，可用环境变量临时覆盖，如 BACKTEST_DAYS=180 SIGNAL_MODE=cross pnpm backtest）
pnpm exec nuxt task run trade:run   # 开发时手动触发一轮（需先 pnpm dev）
```

目录结构：

```
app/                 前端面板（纯客户端渲染）
server/lib/          核心逻辑（纯 TS，不依赖 Nuxt 自动导入，便于单测）
  config.ts          环境变量校验、地址白名单、与面板设置合并
  settings.ts        修改面板设置（含修改预算时重新开始账本）
  exchange.ts        Binance 客户端 + 模拟交易所
  strategy.ts        SMA / RSI 指标与规则信号
  llm.ts             LLM 复核 + 模拟 LLM
  risk.ts            风控规则
  db.ts              SQLite 读写
  engine.ts          一轮决策的编排（含运行锁）
  logger.ts          日志（自动脱敏）
  selfcheck.ts       部署自检
  backtest.ts        回测（真实引擎 + 模拟交易所 + 历史 K 线）
server/tasks/        Nitro 任务 trade:run
server/plugins/      启动、定时触发、优雅退出
server/middleware/   /api 口令校验
server/api/          JSON 接口
shared/settings.ts   面板设置的默认值和校验（前后端共用）
shared/types/        前后端共用的数据类型
tests/               Vitest 单元测试与端到端测试
```
